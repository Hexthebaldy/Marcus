# 手机端前端测试（2026-09-26 至 2026-09-27）

## 环境与方法

- iPhone 18 Pro 模拟器，iOS 27.0，Marcus Debug 应用；Metro 8081、FastAPI 8000。
- 使用电脑操作工具连接 Xcode 的 Device Hub 窗口，实际点击、填写并读取界面和截图，不用接口调用代替手机操作。
- 邮件发往本机 Mailpit，测试邮箱为 `mobile.frontend.qa@example.com`。没有向真实邮箱发送邮件。
- 编辑后台测试 agent 通过浏览器审核手机提交的笔记；图片、视频和活动测试内容也由后台界面建立。
- 测试数据保留在本地开发数据库，标题明确带有“前端测试”或“QA”。没有清空数据库或删除用户原有数据。

## 本轮发现并修复的问题

笔记提交只刷新编辑页的发布状态，未刷新草稿列表。保存草稿触发的列表刷新发生在提交审核之前，因此提交后立即返回时仍显示“草稿”。另外，审核通过状态也被兜底显示为“草稿”。

修复：发布成功后使内容列表缓存失效；内容列表每次重新获得页面焦点时读取最新数据；明确显示“已通过审核”。上表的第二版笔记流程已在修复后实际回归。

### 后续补测中断记录

创建了独立的“前端测试｜输入边界与关联”草稿，没有改变已经公开的两版笔记。完成字数边界验证后，将长正文替换为简短测试说明，并保存地点关联。

测试工具的 accessibility `setValue` 可以直接写入超过原生 `maxLength` 的内容，所以不能用它判断普通输入是否超限。本次边界结论依据 `typeText` 的实际键盘追加结果，不把直接设值绕过限制误报为产品缺陷。

随后点击“重新读取服务器草稿”并进入确认框，电脑操作工具曾返回“Mac is locked”，当时未将后续操作计为通过。2026-09-27 解锁后继续，实际看到“已读取服务器草稿”和“已关联地点”；随后完成活动切换、重新读取与清除关联，结果如下。
