# 共享前端请求客户端测试

在项目根目录执行：

```bash
pnpm --filter @marcus/api-client test
```

本次执行结果：**13 项通过，0 项失败，0 项跳过**。

## 覆盖的行为

1. 访问凭证过期后刷新并重试写请求，保留正文、幂等键和取消信号。
2. 多个请求同时收到 401 时，共用一次尚未完成的刷新请求。
3. 刷新返回 401 时，清除凭证并通知界面登录已失效。
4. 刷新返回 403 时，清除凭证并通知界面登录已失效。
5. 刷新暂时返回 503 时保留凭证，后续请求仍能重新刷新并恢复。
6. Editor Web 即使没有内存中的访问凭证，也能通过 Cookie 刷新；后续请求携带新的访问凭证。
7. 移动端没有刷新凭证时，不发送无效的刷新请求。
8. 登录验证接口返回错误时，不触发递归刷新。
9. 刷新后重试仍收到 401 时停止，避免无限循环。
10. 内容版本冲突保留中文提示、错误详情和请求追踪编号。
11. 服务器返回非 JSON 错误页面时，提供可读提示，而不是 JSON 解析错误。
12. 查询参数正确编码，省略空值，保留数字 0，并接受没有正文的 204 响应。
13. 媒体地址按指定尺寸选择；目标尺寸不存在时，不擅自换用其他尺寸。

## 测试方式与边界

运行器使用项目现有的 TypeScript 编译器，将 `packages/api-client/src/index.ts` 及其引用的真实源码编译到临时目录，再使用 Node 自带的测试工具执行。运行结束后删除临时编译文件。测试没有复制一份客户端实现，也没有新增测试依赖。

测试将 `fetch` 替换为确定性的模拟传输，凭证保存在测试内存中；不会连接真实后端、发送邮件或使用真实账号凭证。因此，结果证明的是客户端在这些指定响应条件下的行为。

这份结果**不代表界面测试或真实后端端到端测试**，也不验证设备存储、浏览器 Cookie 策略、网络可达性或页面交互。并发测试覆盖的是多个请求共用同一次正在进行的刷新，不应扩大为所有可能的网络时序均已验证。

测试文件：`packages/api-client/tests/client.test.cjs`。运行器：`packages/api-client/tests/run.mjs`。
