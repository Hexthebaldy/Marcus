## 后端测试覆盖

- 邮箱验证码创建、到期、尝试次数、重新发送、重复使用与并发验证；网页登录来源校验、登录续期轮换、凭证重放后的撤销。
- 普通用户不能调用编辑或审核接口，不能读取他人私人草稿或媒体。
- Notes 可以纯文字发布，图片顺序保留，不接受专业文档或视频。
- Editor 支持地点和活动重心；活动可以尚未确认地点；封面与图片可空；专业内容块保留。
- 草稿修改不改变公开内容，旧提交的审核不能覆盖新提交，并发保存和重复发布不生成多份有效结果。
- 城市和区的归属检查，公开文章地区、标签随公开版本切换；活动更换场地后详情更新，历史提交保持不变。
- Discover 分页、点赞、收藏、举报、屏蔽与参与记录。
- 工作进程竞争领取任务、领取失效后重新领取、重试与旧进程写回保护。
- 实际 TCP 邮件接收、原邮件发送结果不确定时不盲目重复投递，以及验证码发送后的临时秘密清除。
- 实际 HTTP 对象上传、Pillow 图片处理、FFmpeg 视频转码与封面生成；媒体引用检查、删除及保留期清理。

## 验证边界

用户要求本轮不测试前端，因此没有浏览器操作测试、视觉截图检查、模拟器或真机测试。专业编辑器交互、手机导航、图片选择和实际视频播放体验仍应在后续设备验收时检查。类型检查与资源导出只证明这些构建步骤通过。

对象存储测试使用本地 Moto 提供的兼容 S3 的 HTTP 服务，执行了真实上传和读取请求；这不证明已对接任何生产云厂商。邮件使用本地 SMTP 接收器及 Mailpit，没有向真实外部邮箱发送邮件。

本机没有 Docker，因此没有实际执行 `infra/compose.yaml` 或构建后端容器。此次后端验证使用本机安装的 MySQL、Redis、FFmpeg，以及临时启动的 Moto 和 Mailpit。容器方案和 `.env.example` 已提供，仍需在有 Docker 的机器核对部署。

代码尚未公开部署，没有应用商店签名、生产邮箱域名和正式对象存储配置。首次运行没有预置虚构内容，需要编辑添加地点或活动并审核文章后，Discover 才会出现真实内容。
