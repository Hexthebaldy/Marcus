第 2 课 / 29

把文字、区域和图片放到屏幕上

从两行文字开始，一次只增加样式或图片。

先看练习一的文件 。一个函数返回要显示的界面，React 调用它；View 围住一个区域，Text 显示区域里的文字。它们来自 react-native，不是浏览器的 div 和 p。

独立教学示例：完整组件，展示最小结构；练习中的实际文件可点上面的链接。
import { View, Text } from "react-native";

export default function FirstScreen() {
  return (
    <View>
      <Text>城市笔记</Text>
      <Text>记录今天的发现</Text>
    </View>
  );
}

这两段 Text 默认上下排列。现在切到练习二 ：外层区域增加边距和背景，文字增加字号和颜色。style 接收 JavaScript 对象；StyleSheet.create 把这些对象集中起名，供组件引用，它本身不画任何东西。

教学片段：只保留本课讨论的部分，不是可直接替换整个文件的代码。
<View style={{ padding: 24, backgroundColor: "#E7DFC9" }}>
  <Text style={{ fontSize: 28, color: "#234536" }}>城市笔记</Text>
</View>

padding 写数字，不加 px。要横向排列，给外层加 flexDirection: "row"。RN 并不支持浏览器全部 CSS；先用背景、间距、字号和 Flexbox 就足够画这个屏幕。

最后切到练习三 。Image 的 source 指定图片来源，style 指定显示尺寸。本地图片用 require；网络图片用 { uri: "https://…" }。显示图片不会申请读取用户相册的权限——选择相册里的照片是另一项操作。

第 5 课 / 29

手机切深色时，页面跟着换颜色

读手机当前配色，再挑一组背景和文字颜色。

手机设成深色后，浅底黑字需要换成深底浅字。RN 的 useColorScheme() 会让组件读到当前是 light、dark，或暂时没有结果。我们先准备两组颜色，再选择一组。

教学片段：只保留本课讨论的部分，不是可直接替换整个文件的代码。
const palettes = {
  light: { background: "#F3EDDE", text: "#234536" },
  dark: { background: "#18281F", text: "#F3EDDE" },
};
const mode = useColorScheme(); // 从 react-native 导入
const colors = palettes[mode ?? "light"];

// 组件返回的界面
<View style={{ backgroundColor: colors.background }}>
  <Text style={{ color: colors.text }}>城市笔记</Text>
</View>

mode 是手机提供的选择；palettes 是我们写的对象；colors 指向其中一组。手机配色变化后，组件重新执行，选择另一组颜色。不是把某个 CSS class 加到网页 body 上。

HTML 示意，不是真正的 RN 页面
城市笔记
同一段内容，换一组颜色。

本地 demo 的 app.json 固定使用浅色，所以不要以为切换手机配色已经能改变它。本课展示的是课程主题功能的写法。

第 6 课 / 29

把反复写的配色收进组件

让多个页面使用同一个带配色的文字组件。

如果十个页面都各自读取模式、选颜色、写 Text，就得维护十份相同代码。现在写一个 AppText：里面负责选颜色，页面只传要显示的文字。组件名字是我们起的，不是 RN 内置 API。

独立教学组件：TextProps 是 RN 提供的文字组件参数类型。
import { Text, useColorScheme } from "react-native";
import type { TextProps } from "react-native";

export function AppText({ style, ...props }: TextProps) {
  const dark = useColorScheme() === "dark";
  return (
    <Text
      {...props}
      style={[{ color: dark ? "#F3EDDE" : "#234536" }, style]}
    />
  );
}

props 接住文字等其余参数，再传给真正的 Text。style 单独取出，放在样式数组最后；调用者传入同名样式时，以后面的值覆盖前面的值。页面写 <AppText>城市笔记</AppText> 就能使用它。

本地 展示另一种拆组件：把整张卡片的文字、背景和点击区域收在一起。主题文字组件统一颜色，卡片组件统一一整块界面；两者最终都由 RN 的基础组件组成。

第 8 课 / 29

点击一块区域时执行代码

给卡片加点击动作，并在按住时改变外观。

RN 的 Pressable 包住一块能接收按压操作的区域。打开 ：首页传入 onPress 函数，卡片把它交给 Pressable。函数要等用户点击才执行。

教学片段：只保留本课讨论的部分，不是可直接替换整个文件的代码。
<Pressable
  onPress={() => router.push("/compose")}
  style={({ pressed }) => ({ opacity: pressed ? 0.6 : 1 })}
>
  <Text>写笔记</Text>
</Pressable>

这段中 Pressable、Text 从 react-native 导入，router 从 expo-router 导入。onPress 收到一个函数；函数里的 push 打开发布页。style 也可以接收函数：RN 把是否正在按住放进 pressed，我们据此设置透明度。

不要写 onPress={router.push("/compose")}。那会在生成界面时立即执行 push，而不是等点击。网页 React 的事件函数也遵循同样的区别。

把内容避开刘海和底部手势条

让手机边缘留出系统需要的空间。

如果把按钮直接放在屏幕最底部，可能压在系统手势条下面。本地首页使用 react-native-safe-area-context 提供的 SafeAreaView，让内容避开指定边缘。

删减后的本地首页结构。
<SafeAreaView
  edges={["bottom", "left", "right"]}
  style={{ flex: 1 }}
>
  {/* 页面内容 */}
</SafeAreaView>

edges 指定需要避开的边缘。本地页面顶部已经由 Stack 的导航栏安排，所以这里只列底部和左右，避免顶部重复留白。flex: 1 让这层区域填满父级分配的可用空间。

如果你关闭顶部导航栏，让内容自己顶到屏幕上沿，就要重新考虑 top。不要在所有页面随手写死 paddingTop: 40：不同手机的顶部区域可能不同。

第 12 课 / 29

让手机能请求一个后端

为注册、登录和存书准备服务器。

用户在手机输入邮箱后，账号不能只放在手机数组里；后端要保存账号，并在下次登录时验证凭证。课程使用 Appwrite 提供这些服务。你的手机代码通过它提供的客户端库发请求，Appwrite 服务器处理并返回结果。

手机输入邮箱和密码Appwrite 服务器验证返回成功或失败

课程的 lib/appwrite.js 创建连接对象 client，配置服务地址 endpoint、项目编号 project 和应用标识 platform，再创建操作账号的 account、操作数据库的 databases。它们是前端发请求用的对象，不是运行在手机里的数据库。

配置清单，不是可执行代码。必须使用自己的项目，不能复制课程中的编号。
客户端配置需要三项：
endpoint  → 你的 Appwrite 服务地址

  renderItem={({ item }) => <NoteCard note={item} onPress={() => {}} />}
/>

第 29 课 / 29

删除成功后再离开详情

先删服务器内容，再让列表移除对应项。

用户点击删除后，课程调用 deleteBook(id) 请求 Appwrite 删除那条内容，再导航离开详情。第 26 课的删除通知让共享列表移除它。这里不需要重新删除整张列表。

独立教学片段：deleteNote 是服务器删除函数；这里选择主动更新列表，和课程依靠通知更新的方式不同。
async function removeNote() {
  try {
    await deleteNote(id);
    setNotes((notes) => notes.filter((note) => note.id !== id));
    router.back();
  } catch {
    setError("删除失败，请重试");
  }
}

id 来自详情路径，setNotes 更新共享数组，setError 显示错误。filter 创建一个不含目标编号的新数组，它本身不会删除服务器数据。实际操作前应让用户确认，服务器仍需验证删除权限。若同时处理服务器通知，应按 id 合并，避免重复处理。

本地 demo 没有删除按钮，这段不是已实现功能。学完后再回看项目结构：页面文件负责显示和点击；共享组件负责重复外观；外层 Provider 保存多个页面要用的数据；请求函数负责与服务器来回传数据。现在每一层都有前面操作过的具体事情对应。

页面显示和接收点击共享状态保存数据请求函数访问服务器返回结果更新状态页面重新显示

源码核对补充：原课 deleteBook 同样只打印错误，调用页未必知道删除失败。上面的 deleteNote 必须在失败时抛出错误；这是对错误处理的修正。
